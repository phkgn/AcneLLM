🎯 Mission
Build a fully local, Vietnamese-optimized acne consultation chatbot powered by evidence-based medicine (NICE NG198, AAD guidelines). Features hybrid RAG, safety guardrails, vision integration (Đề tài 27), and advanced retrieval (Đề tài 28).

🔍

Dense (ChromaDB cosine) + Sparse (BM25) + RRF fusion + cross-encoder rerank.
🛡️
Safety Rails
80+ injection patterns, OOD 2-layer check, drug safety, genital scope, pregnancy alerts.
📡
Real-time API

4 Stages 1-4: Preprocessing, Normalization, Snapshot, Guardrails

Stage 1: Input & Preprocessing 📥

1
Load HTTP request (GET SSE / POST / WS)
Query params: message, session_id, mode (auto/hybrid/llm_only), optional temperature
💡 Sample Input
GET /api/v1/chat/stream?message=Em%2022%20tuổi%20bị%20mụn%20viêm%206%20tháng%20nay%20ở%20trán%20và%20cằm&session_id=user_001&mode=auto

Stage 2: NFC Normalization & Session Loading 🧹

2
Text normalization & session history
• Unicode NFC normalize (convert ộ, ứ, etc. to canonical form)
• Remove zero-width chars, control chars, collapse whitespace
• Load JSONL session history (or in-memory fallback)

Stage 3: Rule-based Normalization 🔧

3
Extract clinical fields (regex-based)
Extract using ~900 lines of regex patterns:
age, sex, skin_type, lesion_types (11 types),
distribution (12 body regions), inflammation_level,
medications (check use-context), products (60+ ingredients),
hormonal_factors, allergies, red_flags
📋
Lesion Types Detected
papule, pustule, comedone (open/closed), nodule, cyst, hyperpigmentation, scarring, etc.
🗺️
Body Regions
forehead, cheek, jawline, chin, nose, chest, back, shoulders, neck, temple, chin, lips
💊
Medications Tracked
doxycycline, minocycline, isotretinoin, spironolactone, oral contraceptives, topical treatments
⚖️
Hormonal Factors
menstrual_cycle, PCOS, pregnancy, postpartum, stress, diet, puberty

Stage 4: Snapshot & Session Folding 📸

4
Create NormalizedSnapshot + fold history
• Build NormalizedSnapshot from extracted fields
• Merge with prior turns using smart folding strategy:
  • Age/sex/skin_type: first-write-wins
  • Pregnancy: latest explicit wins (with negation awareness)
  • Meds/products: union + stop-word removal ("ngưng", "dừng", "không dùng")
  • Lesion types: union + dedupe
  • Genital turns: filter out of history block
✅ Stage 1-4 Output
UserInput with populated fields, ready for guardrail checks

4.5 Pre-Check Guardrails 🛡️

Sequence of safety checks:

Check 1
Injection Detection (80+ patterns)
Detect prompt injection: system tokens ([system], <|user|>, ###), jailbreak commands
Check 2
PII Detection (log only)
Detect CMND/email/phone/address — log warning, don't refuse
Check 3
Genital Scope Check (HARD REFUSE)
Before OOD to avoid false negatives. Detect genital/anal region mentions → refuse immediately.
Check 4
OOD Scope Check (2 layers)
Layer 1: keyword check (200+ acne terms vs out-of-scope). Layer 2: embedding cosine vs acne centroid (threshold 0.25). Fail-open if error.

5 Stages 5-7: Planner, Retrieval, Reranking

Stage 5: Clinical Query Planning 🧠

5
Rule-based query generation (no LLM)
Build ClinicalQueryPlan with bilingual queries (VI + EN).
Based on acne signals extracted in Stage 3 → prioritize retrieval direction.
💡 Sample Plan Output
For input "Em 22 tuổi bị mụn viêm ở trán 6 tháng":
queries_vi: ["mụn viêm ở trán", "acne forehead inflammation", ...]
queries_en: ["inflammatory acne forehead", "severe acne treatment", ...]
intent: "treatment"
priority_source_types: ["nice_guideline", "aad_guideline", "pubmed_review"]

Stage 6: Hybrid Retrieval 🔍

6
Dense + Sparse + RRF fusion
• Dense search: query embedding (1024d) → ChromaDB cosine (filter distance ≤ 0.48)
• Sparse search: VI tokenize → BM25 ranking
• RRF fusion: reciprocal rank fusion (k=60) → merge scores
• Trust boost: apply multiplier per source_type (guideline ×1.5, blog ×0.7)
• Score prune: drop scores < 0.015
📊 Trust Boost Multipliers
NICE/AAD: ×1.50 | PubMed review: ×1.20 | Medical site: ×1.0 | Blog: ×0.70

Stage 7: Cross-Encoder Reranking 📈

7
Rerank top-10 candidates → keep top-3
• Use BAAI/bge-reranker-v2-m3 (cross-encoder)
• Score using sigmoid, filter min_sigmoid ≥ 0.30
• Final: drop noisy chunks, truncate context ≤ 4500 chars
• Compute evidence_quality (guideline / journal / web / weak)
🏆
Guideline Evidence
≥1 chunk from NICE/AAD → badge "evidence-based"
📚
Journal Evidence
≥1 chunk PubMed review/JID → badge "research-backed"
🌐
Web Evidence
Medical websites only → "general info"
⚠️
Weak Evidence
Forum/blog or empty context → add disclaimer

6 Stages 8-10: Prompt Build, LLM, Safety Suffix

Stage 8: Prompt Construction 🎯

8
Jinja2 template → escape injection → fill context
• Jinja2 template: stream_user.j2 (system + user blocks)
• Escape injection markers: [system], <|user|>, etc.
• Context block: embed chunks with badges [NICE], [AAD], [PubMed]
• History block: format prior turns (filter genital turns)
• Total context: max 4500 chars
💡 Prompt Structure
[SYSTEM PROMPT: You are an acne specialist...]
[CONTEXT: [NICE] Sebaceous gland... [PubMed] Acne pathogenesis...]
[HISTORY: User: "...". Assistant: "...".]
[USER: "Em 22 tuổi bị mụn viêm ở trán..."]

Stage 9: LLM Generation (SSE Stream) 🚀

9
Call Ollama, stream tokens → SSE
• POST http://localhost:11434/api/chat stream=true
• Model: qwen2.5:7b, temperature 0.4, top_p 0.9
• Yield SSE token events for each chunk
• Auto-fallback: on runner terminated / OOM → retry with qwen2.5:3b

Stage 10: Safety Suffix & Citations 🛡️

10
Append warnings + emit citation events
Safety suffix triggers:
• Pregnant + retinoid mention → ⚠️ "Tretinoin/Isotretinoin contraindicated in pregnancy. See doctor immediately."
• Rx drug mention (isotretinoin, spironolactone) → 💊 "These require prescription."
• Age < 12 → 👶 "See pediatric dermatologist."
• Severe + scarring risk → 🚨 "May be serious — seek medical care."

Citation events: For each chunk in context, emit SSE citation event with {chunk_id, source_name, source_type, url, snippet}
✅ End Result
Complete response with token stream, citations, safety warnings, session saved to JSONL + audit to SQLite

9 RAG System (Stages 5-7)

Query (VI/EN) → Embed (1024d) → Dense: ChromaDB cosine ≤ 0.48
Query → Tokenize VI (underthesea) → Sparse: BM25Okapi
Dense hits Sparse hits → RRF fusion (k=60) → Trust boost (×0.7 to ×1.5) → Score prune ≥ 0.015
top-10 pool → Cross-encoder rerank (bge-v2-m3) → top-3 final → Context ≤ 4500 chars

RRF Fusion Formula

score(d) = Σ over rankings r: 1 / (k + rank_r(d))
         where k = 60 (constant)
               rank_r(d) starts from 1

scripts/crawl_all.py → data/raw/documents.jsonl

Step 2 — Chunk
documents.jsonl → chunks.jsonl (3 phases)

Phase 2: Cross-doc dedup: exact SHA-1 hash + top-20 word shingling (Jaccard ≥ 0.90)
Phase 3: Rebuild metadata AFTER filter to ensure 0 broken links
Step 3 — Embed
chunks.jsonl → ChromaDB (GPU required)
Load chunks → Embedder (Vietnamese_Embedding 1024d, fp16) → upsert batch=32. Idempotent. Skip already-embedded chunks. ⚙️ Requires GPU
Step 4 — BM25
Build sparse index
underthesea tokenize → BM25Okapi → pickle with SHA-256 checksum. Verify checksum on load.

class KBChunk(BaseModel):

    doc_id: str
    text: str                        # ~180 words median

class UserInput(BaseModel):
    age: int | None
    sex: Literal["male", "female"] | None
    skin_type: Literal["oily", "dry", "combination", "sensitive"] | None

17 Troubleshooting

Ollama says "runner terminated"
Backend auto-fallback to 3B. Alternatively: close other GPU apps or reduce LLM_NUM_CTX to 4096.
Backend says "RAG not ready"
Check GET /api/v1/kb/stats. If chunk_count=0: run build_kb.py --step embed. If bm25_ready=false: run --step bm25.
SSE disconnects mid-stream
Check nginx proxy buffering. Set proxy_buffering off. Direct localhost doesn't need this.
Embedding slow on CPU
Vietnamese_Embedding 1024d: CPU ~50 chunks/s, GPU fp16 ~500+ chunks/s. Install CUDA + GPU PyTorch.
Frontend not receiving citations
Check Network tab for citation events with data: prefix. Check CORS origin in CORS_ORIGINS.
OOD check refuses valid questions
Set GUARDRAILS_SCOPE_MODE=soft (default). Mode hard is strict; off disables it.

19 Frequently Asked Questions

Why Qwen2.5 instead of Llama/Mistral?
Better Vietnamese support (especially post-finetune), Apache 2.0 license, many sizes (1.5B–72B) for local flexibility.
Why Hybrid RAG (Dense + Sparse)?
Dense is strong semantically but weak on rare terms (drug names, products). BM25 covers exact-match. RRF fuses them, reducing bias. Important for Vietnamese mixed VI/EN text.
Why rule-based ClinicalPlanner instead of LLM?
Speed + determinism. Each query needs 1 plan — LLM adds 1 extra round-trip, doubling latency. Rules are sufficient given accurate signal extraction.
Does JSONL session scale?
OK to tens of thousands concurrent sessions (1 file each). For larger scale, swap to Postgres/Redis. Interface SessionStoreProtocol is abstract.
Why genital check BEFORE OOD?
Genital content may contain "mụn" keyword → passes acne-centroid check. Genital check is HARD REFUSE, runs first to prevent leaks.
Can I turn off guardrails?
Set GUARDRAILS_SCOPE_MODE=off in .env (dev/test only). Or temporarily modify guardrails module return-pass.
What does "mode=auto" resolve to?
If KB ready AND message has acne signal → hybrid. Else → llm_only (LLM uses prior knowledge, no retrieve).
How does completeness check avoid repetition?
Tracks asked_fields per session → never ask same field twice. Heuristics: knowledge questions skip check; short replies after clarify force check.
