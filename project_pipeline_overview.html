Project Overview

AcneLLM là hệ thống chatbot/tư vấn về mụn trứng cá. Input chính là câu hỏi tự nhiên của người dùng, thường bằng tiếng Việt, có thể chứa slang/teencode, thông tin triệu chứng, sản phẩm đang dùng, thuốc, tình trạng thai kỳ, dị ứng và mục tiêu điều trị. Output chính trong UI là câu trả lời streaming, có thể kèm citations từ knowledge base, metadata về mode, chất lượng bằng chứng, latency và feedback.

Mục tiêu chính

Chuẩn hóa câu hỏi người dùng, phân loại intent, chọn mode phù hợp, lấy bằng chứng từ KB khi cần, dựng prompt có context, gọi LLM và áp guardrails an toàn y khoa.

Data Flow

Runtime chat data

raw_message -> PreparedText -> UserInput + ExtractionConfidence -> RouteDecision + ClinicalQueryPlan -> RetrievalOutput -> prompt -> streamed answer -> session/audit.

  • Session: JSONL dưới data/sessions, lưu turns, snapshots, asked fields, follow-up counts.
  • Audit: SQLite data/audit.db, lưu message/response/chunks/scope/latency/model/entities/PII.
  • Cache: disk cache cho retrieval và embed query, key gồm query/top_k/clinical/safety terms.

KB build data

Seed sources/crawl -> DocumentRaw JSONL -> clean/filter/chunk/dedup -> KBChunk JSONL -> Chroma embeddings + BM25 pickle. Runtime chỉ có RAG khi Chroma dir và BM25 path tồn tại.

  • Crawl: scripts/crawl_all.py, crawler/fetcher.py, crawler/sources/*.py.
  • Chunk: scripts/build_kb.py step_chunk, rag/chunker.py, rag/cleaning.py.
  • Index: step_embed writes Chroma, step_bm25 writes sparse index.

Retrieval & Ranking

Chat path gọi retrieve_for_chat, phía dưới là HybridRetriever. Dense search dùng SentenceTransformer + Chroma; sparse search dùng BM25; kết quả merge bằng reciprocal rank fusion, rồi rerank bằng cross-encoder nếu có.

Error Handling / Guardrails

Input và scope

  • Length guard: MAX_MESSAGE_CHARS=4000, MAX_MESSAGE_WORDS=500.
  • Prompt injection: GuardrailRunner.pre_check raise refusal.
  • PII: detect phone/email/ID and mask before audit.
  • Scope: acne keyword + optional OOD centroid; hard genital-only refusal.
  • Soft scope: out-of-domain can still pass to LLM depending scope_mode.

Generation và output

  • Stream path: appends safety suffix for retinoid/pregnancy, prescription meds, age, urgent red flags and generic disclaimer.
  • Structured path: guardrails.post_check mutates AdviseOutput recommendations/warnings.
  • Drug checker: YAML rule checks plus optional OpenFDA fallback and cache.
  • Runtime exception in stream: emits error frame then done with mode error.
Vấn đề model nhắc nguồn không có trong RAG: prompt templates hiện đã có luật không được bịa nguồn và chỉ được gọi tên guideline/study nếu nó xuất hiện trong retrieved_context. Tuy nhiên nếu model vẫn nhắc AAD khi không có chunk AAD, đó nhiều khả năng đến từ prior của model hoặc Modelfile/system prompt ngoài repo. Code path hiện tại chỉ đảm bảo prompt hướng dẫn và citations frame lấy từ chunks thật; nó không có parser hậu kiểm riêng để chặn mọi tên nguồn được model tự viết trong plain text.

Evaluation / Logging

Evaluation

  • scripts/eval_extraction.py: so sánh golden JSONL với extract_with_confidence, tính scalar accuracy và list micro P/R/F1.
  • scripts/eval_rag.py: generate query set, đánh giá retrieval bằng hit/recall/MRR/NDCG, và có E2E mode gọi chat API rồi judge.
  • src/acne_llm/eval/metrics.py: helper recall/mrr/ndcg/aggregate.
  • src/acne_llm/eval/judge.py: parse AdviseOutput, safety/citation/severity checks.
  • tests: regression tests rộng cho stream, intake, guardrails, RAG, extraction, sessions, eval.

Logging / audit / metrics

  • utils/logging.configure_logging: loguru console/file sinks under data/logs.
  • api/observability.py: request logging, API key, rate limit, in-memory metrics and Prometheus render.
  • AuditStore: SQLite audit log + feedback table; admin routes expose audit/feedback stats.
  • runtime.stream_chat_sse: logs latency, model, used chunks, evidence quality, normalized query, extracted entities.

Dataset / fine-tune helpers

LLMData/chunk_qa, LLMData/clinical_case, LLMData/injection_qa và các script clean/merge/convert trong scripts phục vụ tạo dữ liệu synthetic, validate safety, lọc rule và chuẩn hóa dataset. Đây không phải đường runtime chat chính.
