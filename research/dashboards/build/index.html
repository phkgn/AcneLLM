ĐÚNG

Data → KB → runtime RAG

Crawl và guideline phải qua normalize/chunk/filter, sau đó tạo dense Chroma và sparse BM25. Runtime dùng hybrid retrieval rồi mới cross-encoder rerank.

SỬA TÊN MODEL

Embedding ≠ reranker

AITeamVN/Vietnamese_Embedding là bi-encoder tạo vector. BAAI/bge-reranker-v2-m3 là cross-encoder reranker. Không gọi chung là “BGE-M3 embedding”.

SỬA THỨ TỰ

Dựng frontend/backend/Compose sớm là hợp lý. Nhưng chỉ go-live sau khi GGUF, Modelfile, KB, healthcheck và eval gate đều qua.

      Chunking: contract chi tiết

      Cùng chunker lõi, nhưng web crawl và guideline có gate khác nhau để tránh loại nhầm phần khuyến cáo ngắn.

      WEB CORPUS

      Strict relevance per chunk

      1. Lọc document có quality_score ≥ 0.3.
      2. Clean text, trim quảng cáo/hotline, bỏ listicle/spa/clinic theo title.
      3. Tách đoạn bằng dòng trống; gắn heading vào đoạn sau.
      4. Sentence tokenize bằng underthesea, fallback regex.
      5. Target 200 từ, overlap 40 từ theo câu, minimum 50 từ.
      6. Câu dài >300 từ được cắt trực tiếp theo block 200 từ.
      7. Drop footer/nav, food-domain “trứng cá”, sai ngôn ngữ và chunk không có acne signal.
      8. Cross-document exact + near dedup; ưu tiên trust cao trước.
      9. Rebuild position/prev_chunk_id/next_chunk_id.
      →
      GUIDELINE PDF

      Pre-vetted document, specialized gates

      1. PDF → TXT; giữ provenance URL, language và title.
      2. Chunk cùng 200/40/50; dedup=False trong chunker, dedup toàn tập ở bước sau.
      3. Drop TOC, references, bảng rỗng, boilerplate, quảng cáo, CJK và off-topic.
      4. Guideline chuyên acne không bắt mỗi chunk lặp từ “acne”.
      5. Sách da liễu tổng quát (BYT/An Giang/QĐ 4416) phải có strong acne signal hoặc look-alike cần phân biệt.
      6. Gán nice_guideline, aad_guideline, clinical_textbook hoặc pubmed_review.
      7. Xuất riêng chunks_guideline.jsonl, review rồi mới merge vào corpus chính.

      GENERATOR · 35 SHORT

      Qwen2.5-7B-Instruct QLoRA

      3.465/3.500 records, 16 sample kinds; parity với canonical system prompt; dataset hiện vẫn báo status=incomplete.

      • R1–R10: identity, depth, nonjudgment, empathy, clarification, role boundary, glue, jailbreak, multiturn, special populations.
      • B1–B5: grounded answer, abstain khi thiếu, distractor, conflicting docs, paired depth.
      • K1: knowledge anchor từ KB.
      • 30% user inputs được biến thể teencode/no-accent/typo/mixed; assistant giữ tiếng Việt chuẩn.

      Cách generate data

      Mọi full run phải có deterministic IDs, resume, audit và gates; không lấy eval labels làm train data.

      Intaker factory

      1. Freeze canonical intake SYSTEM + JSON schema/enums.
      2. Relabel golden 985-row legacy corpus; loại invalid/unmappable và eval overlap.
      3. Tính deficit theo 16 quotas; provider sinh đúng JSON constrained schema.
      4. Gate: schema/enums, intent↔fields, negation, jailbreak/no-accent contract, duplicate ID/text, prompt parity.
      5. Top-up chỉ slot thiếu, không regenerate row hợp lệ.
      6. Deterministic split 90/10 → 3.600 train + 400 val.

      datagen/intakedata/{config,seed,generator,gates,pipeline,writer}.py

      Generator factory

      1. Freeze system_prompt.canonical.txt byte-identical với Modelfile.
      2. Allocate 3.500 quota theo R/B/K taxonomy.
      3. Với B/K, sample context thật từ data/raw/chunks.jsonl; render prompt riêng theo case.
      4. Provider generation, JSON parse và deterministic gates: role, safety, grounding, abstain, conflict, knowledge accuracy, phrase frequency.
      5. Audit provider/content failures; retry bounded, resume by deterministic ID.
      6. Stratified split 85/8/7 với safety cases bắt buộc trong holdout; export ShareGPT.

      datagen/roledata/{taxonomy,anchor,generator,gates,pipeline,finalize}.py

      KẾT LUẬN CÓ BẰNG CHỨNG

      Generator local là bottleneck lớn nhất

      Thay duy nhất generator bằng deepseek-v4-pro, giữ canonical SYSTEM và phần còn lại, tăng answer quality khoảng +1 điểm. Oracle intake gần 0 về quality; oracle RAG chỉ +0,25.

      CHƯA ĐỦ ĐỂ RELEASE

      Còn thiếu calibration + production E2E gate

      Judge cùng provider với frontier arm có nguy cơ bias; cần human calibration/second judge, direct RRO−RNO pairing, SSE TTFT/total latency, citation/grounding audit và một atomic rerun.
